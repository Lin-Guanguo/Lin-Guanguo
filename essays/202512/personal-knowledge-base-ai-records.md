# 个人知识库：让 AI 帮我记录工作

这篇文章分享我用 Claude Code、Git 和聚合脚本搭建的个人知识库系统：日志自动生成、周报一键汇总、长期事项随时可查。「记录」从负担变成了习惯。

### 它能帮我做什么？

**日常**
```
我：dailylog 1218

AI：日志已生成。今日完成 3 项：LLM Memory 调研、盲测功能上线、发布时区修复。
    新增 TODO 1 项，进行中 2 项。确认提交？

我：commit
```
终端里简短确认，详细内容在生成的 markdown 文档里。

**周会**
```
我：weeklog

AI：本周完成 8 项，重点：业务平台上线、图片监控完成。
    进行中 3 项，新增 TODO 2 项。确认提交？
```
周五开会前跑一下，直接汇报。

**绩效/OKR**
```
我：帮我总结 10-12 月的工作重点

AI：Q4 主要产出：业务平台（完整交付）、LLM Memory 调研、
    Agent 可视化编码系统...共 47 项完成，12 项进行中。
```
再也不用翻三个月前的聊天记录。

**追踪遗漏**
```
我：XX 功能做到哪了？

AI：11/20 提出，11/25 开始开发，12/03 后无更新。
    最后状态：完成 80%，阻塞点是等设计稿。
```

**每日规划**
```
我：今天主要任务是什么？

AI：P0 进行中：平台上线验证、图像能力限流对接。
    P2 长期 TODO：Agent 代码重构，上次跟进是 12/10。
```

### 核心架构

所有工作都用 Git 管理，但不能把所有东西塞一个仓库——太乱，看不清主线。

我的做法：
- 每个项目独立 Git 仓库（代码、调研、文档各自分开）
- 知识库是单独一个仓库
- **`fetch-today-work.sh`** 脚本把外部仓库的今日工作聚合进来

```bash
> ./scripts/fetch-today-work.sh -d 2025-12-18

[OK] project-a: 13 commits, +13905/-759
[OK] project-b: 3 commits, +3002/-280
[OK] llm-memory-research: 7 commits, +6236/-7
```

脚本扫描所有配置的仓库，提取今天的 commits 和 diff，存到 `.work-cache/`。然后 AI 读取这些内容生成日志。

**核心思路**：外部工作仓库的路径配置在脚本里，知识库自动拉取各仓库的 commits 和 diff。**工作本身就是记录，commit 就是日志的原材料。**

各仓库保持独立清晰，知识库只做聚合和总结。

---

### 三个核心原则

**1. Git 管理一切**
代码用 Git，知识也用 Git。版本化、可追溯、多设备同步。

**2. 定期聚合**
日志 → 周总结 → 月总结 → 年总结。信息压缩，不会越积越多。

**3. 本地化**
数据在你手里，不锁在任何云服务。AI 工具换代了？随时切换。

### 未来畅想

现阶段 AI 干活还需要我很多干预——提供上下文、解释背景、纠正方向。本质上是我知道很多 AI 不知道的事情。

但如果 AI 知道我的一切呢？

我的工作习惯、项目历史、技术偏好、踩过的坑、做过的决策……全部记录在案，随时可查。到那时候，我只需要说「把这个功能做了」，剩下的交给它。

**这是我的梦想：让 AI 替我干活，而我只负责提想法。**

知识库就是第一步。
